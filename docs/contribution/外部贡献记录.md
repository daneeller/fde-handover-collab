### #7102 维护者互动与技术结论

维护者 `ndonkoHenri` 于 2026-11-19 回复，指出三点：

1. 0.86.5 与 1.x 中，事件处理器/`main()` 内的异常不会结束应用，Flet 会以 ERROR 记录并显示在窗口内；
2. `Session was garbage collected` 是会话结束的 INFO 记录，桌面端对应窗口 client 进程退出；
3. 真正会丢异常的有两处：`page.run_thread()` 内的异常（被线程池吞掉，`threading.excepthook` 看不到）、以及 PyInstaller 无 console 时日志落到 stderr。

我方用本项目日志作出回应（[回复正文](./flet-issues/01-reply-to-maintainer.md)），确认并修正了原始判断：

- 打包方式为 **PyInstaller 直接打包 + `console=False`**，不是 `flet pack` / `flet build windows`；但已配置 `RotatingFileHandler` 落盘，因此「日志丢失」不是本项目的原因。
- 日志中存在完整证据链：`ERROR [concurrent.futures] exception calling callback for <Future ...>` → `flet/controls/page.py:870 _on_completion raise exception` → 应用帧 → `TypeError`；随后 16 秒才出现 `INFO [flet] Session was garbage collected`，应用**未崩溃**并正常重启。
- **修正**：原报告把日志末尾的 `Session was garbage collected` 读作崩溃原因，实际是窗口关闭的症状；维护者的假设成立。
- **新发现**：该异常的记录者是 `concurrent.futures` logger 而非 `flet` logger，因此按 `flet` 过滤会完全漏掉；已向维护者询问 1.x 是否改过归属。

**关闭结论（2026-11-19 深夜，维护者 `ndonkoHenri`）**：1.x 与 0.86.5 行为一致（logger 归属问题确认存在）；由于归属问题已由我方拆出的 #7109 单独跟踪并修复，#7102 作为"整体可诊断性"主题被友好关闭。维护者明确采纳了我方回复的结论：早期"静默退出"是窗口/client 正常关闭，不是未捕获异常。

未单独拆出的两点：
- `run_thread` / `run_task` 线程语义：当前 1.0 `async-apps.md` 已写清，无重复提交价值。
- 首帧 `update()` 需让出事件循环：已由 PR #7101 的文档补丁覆盖。

## 第二轮独立 Issue（2026-11-19，基于 0.86.5 与 main 分支源码逐行核实）

主题：跨线程 UI 更新的框架层线程安全契约。正文归档在 [flet-issues/](./flet-issues/)：

| Issue | 主题 | 关键证据 |
|---|---|---|
| [#7107](https://github.com/flet-dev/flet/issues/7107) | `Page.update()` 线程安全未文档化 + `run_thread()` 被普遍误读为“回 UI 线程” | 0.86.5 `messaging/session.py` 全文件无锁、`patch_control` 在调用线程同步执行；main 分支 1.x 的 `__update` 仍直通 `patch_control`，调度器只覆盖响应式通知路径 |
| [#7108](https://github.com/flet-dev/flet/issues/7108) | 1.x `Session.schedule_update()` 用 `asyncio.Event.set()`，跨线程调用不安全 | main 分支源码：`asyncio.Event` 官方文档明确非线程安全；公开方法 docstring 未禁止外部线程调用 |
| [#7109](https://github.com/flet-dev/flet/issues/7109) | `run_task()` 后台任务异常记录在 `concurrent.futures` logger 而非 `flet` logger | 本地打包应用真实日志：`ERROR [concurrent.futures] exception calling callback ... page.py:870 _on_completion raise exception`；按 `flet` 过滤日志会完全漏掉 |

其中 #7107 的动机链：我方项目曾把「UI 更新一律经 run_thread」写成门禁约定，
源码核实后发现该约定并未消除竞态（run_thread 进的是线程池而非事件循环），
据此重构了项目侧桥接并向框架报告了根因。

## 三、逐条来源说明

### P1 技术方案提示词

- **来源**：来自 `docs/技术方案.md` 的生成过程，输入材料 8 项在 `技术方案提示词.md` 第一节列明。
- **可复现**：按输入清单喂材料 → 粘贴主提示词 → 用 12 项自检表核对。
- **注意**：该提示词产出的是**文档**，不是运行时代码；这是高分仓库被扣分的根因，因此补充 P2–P5。

### P2 缺陷定位辅助提示词

- **来源**：`03-现场调研分析/现场调研报告.md` 任务 1 —— 一线痛点"缺陷描述和照片对应不上户型部位、分包看不懂返工位置"（f10），关键说明留在便签或群消息、未随单据交接（f14）。
- **约束来源**：f42 要求 98% 是定位准确率且口径未定；f15 要求错误结果不覆盖原记录。
- **落点**：`src/prompts.py` 中模板与 `src/locator.py` 的 `rule` / `prompt` 双模式一一对应。
- **自检**：运行 `python src/main.py --mode prompt --demo`，确认输出含 f10/f15/f42 且声明"不关单"。

### P3 红线判定提示词

- **来源**：`03-现场调研分析/现状流程图.md` 第 2 节四类异常触发（f11/f44），第 4 节瓶颈责任标注；技术方案第七章代理职责。
- **落点**：`src/rules.py::detect_red_lines` 的 R1–R4 与提示词检查项逐条对应。
- **自检**：`python -m unittest discover -s tests -v`，test_03 至 test_06 覆盖四类触发。

### P4 审计留痕规则

- **来源**：技术方案第十章"审计留痕六要素"（f45）；角色边界 f22（不能代替专业签核）。
- **落点**：`src/audit.py::build_audit`，人工改动与签核人字段留空（"待人工填写"），不自动填。

### P5 字段去重与快照规则

- **来源**：现状流程图第 3 节"一条缺陷拆多张工单 → 复验通过率重复计数"（f31），须校验主编号/事件时间/版本字段（f33），接口中断用带时间戳快照（f35）。
- **落点**：`src/rules.py::dedupe_by_master` 与 `stale_snapshot`。

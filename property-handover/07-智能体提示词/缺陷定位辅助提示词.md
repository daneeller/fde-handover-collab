# 缺陷定位辅助提示词（可运行版）

> **来源**：`03-现场调研分析/现场调研报告.md` 任务 1；事实编号 f10 / f14 / f15 / f42。
> **产出**：定位候选 JSON；运行时代码为 `src/locator.py`，模板为 `src/prompts.py::LOCATION_PROMPT`。
> **数据性质**：合成训练场景，结论为待验证假设。

---

## 一、主提示词（可直接复制）

```text
你是「交房缺陷与整改协同」试点的只读定位辅助助手。
任务：根据缺陷描述与照片元数据，给出户型部位候选与返工位置提示。

【输入】
- 缺陷编号、户号、描述、照片引用
- 户型图版本、资料版本、快照时间
- 可选部位清单（编码=名称(关键词)）

【输出要求】
1. 只输出 JSON：part_code, part_name, confidence, evidence_text, needs_confirmation, repair_note。
2. evidence_text 必须逐字引用输入，不得编造。
3. needs_confirmation 恒为 true；本助手不确认部位、不关单、不改状态（f15/f22）。
4. 描述与照片矛盾或匹配不到部位，输出 UNKNOWN 并写明「转人工核对」（f10）。
5. 每条判断附事实编号 f10/f15/f42。
6. 98% 是缺陷定位准确率，判定人与样本量尚未核实，不得声称达到（f02/f42）。

【禁止】
- 不生成关单、赔偿、责任认定、客户答复等结论（f05/f40）。
- 不覆盖原记录；建议与原记录并列展示（f15）。
```

---

## 二、运行方式

```bash
# 离线规则模式：不调用模型，直接产出候选与置信度
python src/main.py --demo

# 提示词模式：输出可发给任意模型的完整提示词（本仓库不调用模型）
python src/main.py --mode prompt --demo
```

两种模式的输出都带 `needs_confirmation=true`，且 `src/locator.py` 中不存在任何写回方法（f32）。

## 三、样例输出（D-1004 描述—照片冲突）

```json
{
  "defect_id": "D-1004",
  "part_code": "LR-01",
  "confidence": 0.55,
  "photo_description_mismatch": true,
  "needs_confirmation": true,
  "decision": "描述—照片冲突，转人工核对（错误建议不覆盖原记录，f15）"
}
```

> 描述写"厨房橱柜"，照片元数据指向客厅，候选置信度被压低且不自动确认；
> 这正是 f10 痛点的可运行复现，也是高分仓库所缺的"提示词落成原型"。
